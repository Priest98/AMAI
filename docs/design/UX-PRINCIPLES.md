# Oyinca UX Principles

1. **Make the next decision obvious.** Each region presents one dominant action and names the resulting state.
2. **Show the work honestly.** Distinguish queued, processing, ready, scheduled, published, failed, and stale states. Never invent activity or metrics.
3. **Keep creators in control.** Approval, autopilot, scheduling, billing, and destructive changes explain consequence before commitment.
4. **Preserve effort.** Keep form values and drafts through recoverable errors; retries should not duplicate work.
5. **Reduce cognitive switching.** Keep brand, platform, date, timezone, and active workspace visible where they affect a decision.
6. **Reveal depth when asked.** Put the common path first; place advanced settings and diagnostic detail behind explicit disclosure.
7. **Design empty and failed states as core screens.** New accounts and API failures are normal product states.
8. **Use motion as feedback.** Animation confirms relationship or progress and remains optional.
9. **Respect every input mode.** Keyboard, touch, zoom, screen reader, and reduced motion receive complete workflows.
10. **Let the product earn trust.** Clear language, reversible actions, timestamps, and visible ownership matter more than decorative polish.
