## Shared state contract

Every data surface distinguishes pending, successfully empty, populated, unavailable, stale and restricted. Successful emptiness has a relevant next action; network failure has recovery. Brand/account and date scope accompany actionable content. Never replace a failed request with an invented result. Do not announce a user action as successful until the API confirms it.

## Mobile transformations

Public island becomes compact menu; acquisition content follows readable document order. Dashboard retains bottom navigation; status and next task lead. Composer becomes sequential preview/form sections, review keeps decisions reachable, calendar shows day groups, dense tables use labeled rows or local scroll. Notifications and dialogs use bounded sheets with keyboard-safe actions. Both touch and keyboard must have a complete path.

## Measurement and QA handoff

Record consent-appropriate stage outcomes such as setup saved, account ready, asset registered, draft prepared, approved and provider confirmed. Do not send raw captions, credentials, private Brain answers or replay private screens. Existing privacy policy governs instrumentation.

Phase 2 gate: local runtime stable, tokens/primitives/acquisition approved, responsive/keyboard/reduced-motion tests pass. Phase 3 gate: existing contracts and plan rules preserved, saved state truthful, client isolation proven. Phase 4 gate: every above flow tested with populated/empty/error states at 1440, 1280, 1024, 768, 430, 390 and 360px; production build and review completed. No actual billing transaction or public post is required for design-only QA; use controlled test flows for mutations.
